# Product management UI enhancements

Adds initial stock input, product variants UI, and 2-column grid layout for product cards. The ProductCard component was refactored to show image, name, and price in a compact card suitable for grid display, the add-product form now accepts initial stock quantity and includes a variants section with add/remove functionality, and the products index displays cards in a 2-column grid with proper spacing.

**Watch for:** Variants UI is non-functional (confirmed) — the form collects variant data but doesn't persist it to the database or display it anywhere else. The schema field was removed but the UI section remains.

**Verdict**: NEEDS_CHANGES

## High-level view

The ProductCard was streamlined to support 2-column grid display with a 1:1 aspect image container, name/price layout, and compact badges. Category is not visually displayed but remains in the Product type.

The add-product form includes `initialStock` in the schema and passes `initialQuantity` to the mutation. The productRepository accepts and uses `initialQuantity` instead of hardcoding 0. The useCreateProduct hook's mutationFn type includes `initialQuantity`.

The products index uses `numColumns={2}` with `gridContent` and `columnWrapper` styles for 2-column layout.

The variants UI collects data but doesn't persist or use it anywhere — no database schema, no submission logic, no display elsewhere in the app.

## Variants section behavior

The add-product form declares:

```typescript
const [variants, setVariants] = useState<{ name: string; price: string }[]>([]);
const [variantName, setVariantName] = useState('');
const [variantPrice, setVariantPrice] = useState('');
```

The UI section (below initial stock) renders a "Product Variants (Optional)" heading, helper text, a list of added variants with name/price display and a remove button, and input fields for adding new variants with an "+ Add Variant" button.

The "+ Add Variant" button's onPress:

```typescript
onPress={() => {
  if (variantName.trim() && variantPrice.trim()) {
    setVariants([...variants, { name: variantName, price: variantPrice }]);
    setVariantName('');
    setVariantPrice('');
  } else {
    Alert.alert('Error', 'Please enter both variant name and price');
  }
}}
```

adds the variant to local state. The remove button filters it out by index.

The `saveProduct` function calls:

```typescript
await createProduct.mutateAsync({
  name: data.name,
  description: data.description || undefined,
  barcode: data.barcode || undefined,
  categoryId: data.categoryId || undefined,
  purchasePrice: toMinorUnits(parseFloat(data.purchasePrice)),
  sellingPrice: toMinorUnits(parseFloat(data.sellingPrice)),
  unit: data.unit,
  minStockThreshold: minThreshold,
  initialQuantity: initialStock,
  localImagePath: imageUri,
});
```

The `variants` state is never referenced. The productRepository.create method has no `variants` parameter. The database schema (not shown in the diff, but inferred from repository absence) has no variants table or relation.

The commit message "refactor: remove non-functional variants UI from add-product form" is contradicted by the current code — the variants UI is still present in the latest commit (58d27f1).
