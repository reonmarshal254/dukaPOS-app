# Product management UI enhancements

The product management system now supports initial stock quantities, product variants, and a 2-column card-based grid layout. The add-product form includes comprehensive input validation with initial stock and variant management. The product list displays cards with images, names, and prices in a responsive grid.

**Watch for:** Variants UI is non-functional (confirmed) — the form collects variant data but never persists it to the database or uses it. The repository `create()` method signature lacks a `variants` parameter, and no variant-related database operations exist.

**Verdict**: NEEDS_CHANGES

## High-level view

The add-product form now captures initial stock quantity through an `initialStock` field that's validated in the schema and passed to the repository as `initialQuantity`. The repository accepts this parameter and uses it to set `current_quantity` at product creation time instead of hardcoding zero.

The product card component renders in a card layout optimized for a 2-column grid: 1:1 aspect ratio image at the top, product name and price below, with compact low-stock and out-of-stock badges. Category display was removed from the card itself, though category filtering remains available in the product list screen.

The variants section in the add-product form provides add/remove UI with name and price inputs, but the implementation is incomplete — variants are collected in component state but never passed to `createProduct.mutateAsync()`, so they're discarded on submission.

TypeScript compilation passes with no errors.

## Initial stock input wired through to repository

The add-product form schema includes `initialStock` as a required string field with validation for minimum length and numeric parsing. The form's `saveProduct` function parses it to an integer, validates it's non-negative, and passes it as `initialQuantity` to `createProduct.mutateAsync()`.

## Variants collected but never sent

The add-product form maintains a `variants` state array with `{ name: string; price: string }[]`. The UI renders a list of added variants with remove buttons, and provides name/price inputs with an "Add Variant" button that appends to the array.

When the form submits, the `saveProduct` function calls `createProduct.mutateAsync()` with the following parameters:

```typescript
await createProduct.mutateAsync({
  name: data.name,
  description: data.description || undefined,
  barcode: data.barcode || undefined,
  categoryId: data.categoryId || undefined,
  purchasePrice: toMinorUnits(parseFloat(data.purchasePrice)),
  sellingPrice: toMinorUnits(parseFloat(data.sellingPrice)),
  unit: data.unit,
  minStockThreshold: minThreshold,
  initialQuantity: initialStock,
  localImagePath: imageUri,
});
```

The `variants` state is never referenced in this call. The `useCreateProduct` hook's `mutationFn` signature does not include a `variants` parameter, and the `productRepository.create()` method does not accept variants. No variant-related database operations exist in the repository layer.

## ProductCard layout for 2-column grid

The card uses a 1:1 aspect ratio container (`aspectRatio: 1`) for the image section at the top, followed by a content section with padding. The image is rendered using `expo-image`'s `Image` component with `contentFit="cover"`. When no image is present, a placeholder renders a centered 📦 emoji on a dark surface background.

Category information is not displayed on the card itself. The `category` prop is accepted but unused in the current implementation.

## Products index grid styles

The products index screen renders a `FlatList` with `numColumns={2}`. The `contentContainerStyle` applies `styles.gridContent` with padding on all sides, and `columnWrapperStyle` applies `styles.columnWrapper` with `gap: SPACING.sm` to create spacing between columns.

```typescript
gridContent: {
  padding: SPACING.md,
  paddingBottom: SPACING['3xl'],
},
columnWrapper: {
  gap: SPACING.sm,
},
```
